Always use absolute paths or paths from the repo root in commands; do not rely on the shell's current directory. Do not commit unless asked. Do not edit `services/profile`, `services/identity-access` or any sibling service.

Build rules that every task must respect (they already fail the build, see research R12): log calls must not mention `password`, `hash`, `token`, `secret`, `credential` or `privateKey` (name log arguments `userId`, `publicId`, `attempts`, `eventId`); no class name may contain `Outbox`, `Cdc`, `Debezium`, `DomainEvent`, `IntegrationEvent`, `EventDispatcher`, `AggregateRoot` or `AssetReference`; classes named `*Row`, `*Rows`, `*Record`, `*RowMapper`, `*RecordMapper` in infrastructure must be package-private.

## Phase 4: User Story 2 - Edit my display name and bio (Priority: P1)

**Goal**: A signed-in user saves a display name and/or bio; the first save creates the profile; omitted fields stay unchanged; invalid values are refused with a message naming the rule; concurrent saves never mix.

**Independent Test**: With a user that has no profile, `PATCH /api/v1/profiles/@me` with a display name (204); read back; `PATCH` a bio only; read again and see both. A 33-character name returns `400` naming the rule, and nothing changes.

## Dependencies & Execution Order

### Phase dependencies

- **Phase 1 (Setup)**: none.
- **Phase 2 (Foundational)**: after Phase 1; blocks every story.
- **Phase 3 (US1)** and **Phase 4 (US2)**: after Phase 2; US2 reuses the controller and `ProfileRepository` port but not US1 code paths, so they can run in parallel by two developers. US2's e2e test (T039) is the first that uses both.

Tests first (they should fail), then model and ports, then services, then adapters, then presentation, then the end-to-end test.
